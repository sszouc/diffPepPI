# 基于条件离散扩散模型的蛋白质结合肽生成

给定一条蛋白质的序列，用掩码式离散扩散模型（masked diffusion）生成可能与它结合的多肽。
课程设计项目，代码可复现。技术栈：PyTorch、Transformer、离散扩散。

## 1. 任务与数据

任务：输入蛋白质的表征，生成结合肽序列（长度 5~30），即建模 `p(肽 | 蛋白)`。

**数据来源：Propedia 26**（73,392 个蛋白–肽复合物中清洗出的高质量子集）。

清洗条件（见 [`data/sequence.py`](data/sequence.py)）：

- 肽长度 5~30（排除过短/过长）
- 肽序列不含未知氨基酸 `X`
- `BPP% >= 20`（肽的包藏嵌入比例，避免肽大部分游离在溶剂里）
- 分辨率 ≤ 3 Å（排除 NMR 及低分辨率结构）
- 只保留条目数 ≥ 50 的物种（避免罕见物种污染）

## 2. 方法

```text
蛋白序列 ──ESM2-650M──▶ 逐残基表征 [L,1280] ─┐
蛋白 3D 结构 (PDB) ──▶ CA 坐标 + 界面标注 ───┤
                                             ▼
                                  StructureEncoder (4 层 EGNN)
                                             │
                       ┌─────────────────────┼──────────────────────┐
                       ▼                     ▼                      ▼
                  memory (L+1,256)     iface_logits (L)        全局 ESM 均值
                  = 全局token + 残基     → 辅助 BCE 损失            → 长度预测器 → k
                       │
                       ▼
              去噪网络 (4 层 TransformerDecoder) ◀── 采样窗口 0..k-1
                       │
                T=100 步去噪 ──▶ 肽序列
```

### 2.1 掩码扩散过程

前向加噪：时间步 `t ∈ {0, ..., T-1}`，掩码率 `p_t = t/(T-1)`，
序列的每个位置以概率 `p_t` 被替换为 `<MASK>`；`<PAD>`、`<X>`、`<EOS>` 三类不参与加噪。
`<EOS>` 也排除的理由：它的位置由长度分支预先给定，采样时概率被置 0、不参与去噪；
若允许遮蔽，模型还能从未遮蔽的 `<EOS>` 直接读出长度，造成信息泄漏。

反向去噪：从全掩码出发，每一步只对被遮蔽的位置重新采样。对吸收态扩散，
反掩码概率有闭式解 `1 - p_{t-1} / p_t`，不需要额外学一个转移网络。实现见 `diffusion.p_sample_loop`。

训练损失（`train.masked_loss`）：把加噪后的 `x_t` 送进网络预测每个位置的原始 token，
交叉熵只对被加噪的位置计算，另外补上 `<EOS>` 位置：

- 未加噪的位置不计损失。模型看得见它们（实测准确率 100%、loss 仅 0.003），
  算进去只是把分母稀释掉；而且采样时只用被遮蔽位置的预测，未遮蔽位的输出根本用不到。
  实测 t=50 时未加噪位占有效位的 51%，旧口径会把损失拉低约 0.02。
- `<EOS>` 位置计入。它永不加噪，但必须学会"到此结束"；若不补这一项，
  `<EOS>` 在本设计下会完全失去监督。
- `<PAD>` 与 `<X>` 天然被排除：既不加噪、目标也不合法。

### 2.2 结构编码器（`struct_encoder.StructureEncoder`）

用蛋白 3D 结构 + 逐残基 ESM 表征，产出交叉注意力的 memory 和一个界面预测头。

| 组件 | 说明 |
|---|---|
| 节点特征 | 氨基酸 embedding(32) + 逐残基 ESM(1280→128) + `present`/`imputed` 两个标记 |
| 坐标 | CA 三维坐标；`<X>` 与末端缺口由 `node_mask` 屏蔽 |
| 图 | Cα kNN（k=16），边特征 = 距离的 8 点 RBF 展开 |
| 主干 | **4 层 EGNN**（E(n) 等变图网络，**无坐标更新**，见下） |
| 全局补足 | EGNN 感受野有限（实测 4 层在 251 残基上只覆盖 78%），所以每个残基的输出再拼上**全蛋白池化向量** |
| 输出 memory | `(B, L+1, 256)` = 1 个全局 ESM token + L 个残基表征 |
| 界面头 | 逐残基 1 维 logits，`BCE` 辅助损失（权重 `IFACE_LOSS_WEIGHT=0.5`） |

**EGNN 为什么只用距离**：消息只由 `‖x_i − x_j‖` 决定，所以残基表征对旋转/平移不变。
参数量约 **1.08 M**。

**为什么没有坐标更新分支**：标准 EGNN 会把坐标也一起更新（`x_i += C·Σ(x_i−x_j)·φ(m)`），
只有需要**等变向量输出**（如生成结构）时才有必要。本任务只需要**不变**的残基表征去喂交叉注意力，
所以去掉了这一支。这不只是简化，也是修 bug：

> 实测训练到第 2 个 epoch 时出现 NaN。逐层定位发现 `h` 在第 4 层之后有若干位置变成 NaN，
> 而 `cond`、输入坐标、`esm` 全部正常——根因是坐标更新让部分节点坐标漂移，
> 使层间距离平方 `d²` 溢出 float32（`inf`），进而污染几乎全部参数梯度。
> 修复方式是**去掉坐标更新 + 把距离特征有界化**（`d/(1+d/20)` 代替无界的 `d²`）。
> 另外在训练循环里加了梯度裁剪和非有限 loss 的 batch 跳过，防止单个异常 batch 毁掉整个模型。

**为什么把界面标注当"辅助标签"而不是输入**：推理阶段面对的是没见过的新蛋白，
**此时不知道它的结合位点**。把真实界面当选条件会造成"输入在推理时不存在"的泄漏。
所以让编码器看整条蛋白链、自己学口袋表征，界面标注只用来加一个辅助监督头。

**长度上限**：结构分支最多 512 个残基（`STRUCT_MAX_LEN`）。蛋白长度 P50=237 / P90=359 /
P95=429，截断只影响 3.2% 的复合物。

### 2.3 去噪网络（`model.ConditionalDecoder`）

| 组件   | 说明                                                             |
|------|----------------------------------------------------------------|
| 输入   | `x_t`（B×51）、时间步 `t`、`memory`（B×(L+1)×256）、`memory_mask`         |
| 词嵌入  | 24 个 token 的嵌入表（20 氨基酸 + `<EOS>` + `<PAD>` + `<MASK>` + `<X>`） |
| 位置嵌入 | 可学习，51 个位置                                                     |
| 时间嵌入 | 正弦嵌入 + MLP，广播加到每个位置                                            |
| 主干   | 4 层 `nn.TransformerDecoder`，双向自注意力                             |
| 条件注入 | 交叉注意力：Q 来自肽，K/V 来自结构编码器的 `memory`                              |
| 输出   | 21 类打分（20 种氨基酸 + `<EOS>`）                                      |

去噪任务是双向的：每个位置都要能看到整条序列，因此不加因果掩码；
肽尾部的 `<PAD>` 通过 `tgt_key_padding_mask` 屏蔽，`memory` 的 padding 通过
`memory_key_padding_mask` 屏蔽。

**条件注入是变长的**：肽的 51 个位置各自对 `L+1` 个 memory 位置算注意力权重
（旧版只有一个全局向量）。这也是保留 `TransformerDecoder` 而非改成 `Encoder`
的实际收益——换成变长条件时不需要重新设计序列拼接。

**结构编码只做一次**：蛋白条件与扩散时间步无关，所以每个 batch（无论训练、验证的
4 个时间步，还是采样的 100 步）都复用同一份 `memory`。这是采样可行的关键——
否则每步都要重跑 EGNN。

### 2.4 长度预测分支（`model.LengthPredictor`）

肽长不固定（5~30），因此单独用一个分支预测长度：

- 结构：MLP `1280 → 256 → 256 → 51`，输出 `k = 0..50` 的长度分布，交叉熵训练
- 独立训练：与去噪网络各用一个 AdamW 优化器，每个 batch 先更新长度分支再更新去噪分支
- 生成时采样长度：从预测分布采样 `k`（而不是取 argmax）。采样保留了分布形状，
  同一蛋白的多条候选肽长度也自然不同；argmax 会一直偏向众数
- 长度不作为网络输入：`k` 只用于构造采样窗口（`0..k-1` 待采样、第 `k` 位放 `<EOS>`、其余 `<PAD>`）

**验证指标为什么不用"准确率"**：早期报的是 argmax 命中率（exact match），但它有两个问题：

1. **与生成方式矛盾**：生成时是从分布里采样，而准确率评估的是 argmax —— 模型不会采用这个决策。
   一个很好的分布估计器，argmax 命中率也可以很低；反之 argmax 高的模型往往塌缩到众数、丧失多样性。
2. **区分不出好坏**：真实长度高度集中在 8~11（众数 9 占 17.3%），
   "永远猜 9"就有 17.3% 的准确率，而"从边际分布采样命中真实值"的期望是 7.3%。
   实测模型的准确率就在这个量级，说明这个指标没有信息量。

因此改为报三件事，并与**边际基线**对比：

| 指标 | 含义 |
|---|---|
| **NLL (nats)** | 真实长度在预测分布下的平均负对数似然 —— 就是训练目标本身 |
| **top-5 命中率** | 真实长度是否落在预测的前 5 名（对宽分布更稳健） |
| **E[k] MAE** | 预测期望长度与真实长度之差的平均值 |
| **边际基线 NLL** | 完全忽略蛋白条件、只用训练集长度分布预测时的 NLL |

**判读**：只有当模型 NLL 明显低于边际基线，才说明长度**确实用上了蛋白条件**；
若两者接近，长度分支只是在学一个先验分布，不应在结论里夸大。
生成时真正关心的是**采样出的长度分布与真实分布的 TV 距离**，由 `evaluate.py` 报告。

**首次使用需按顺序跑两步预处理**（见第 4 节）：

1. `python build_align.py` —— 解析 10,813 个 PDB，产出结构缓存与对齐质量表（约 40 秒）
2. `python split_pkl.py` —— 拆分 7.2 GB 的残基表征 pkl（需先腾出 ≥ 8 GB 可用内存，约 5~10 分钟）

训练时每个 epoch 只写一个 `checkpoints/model_last.pt`，
并在验证损失刷新最优时另存一份 `checkpoints/model_best.pt`：
- **验证损失是确定性的**：固定在一组时间步 `VAL_T_STEPS = (25, 50, 75, 99)` 上算，
  掩码随机场由独立生成器（种子 = `SEED`**）给出。**
- **早停**：连续 `EARLY_STOP_PATIENCE = 10` 轮验证损失没有改善（改善幅度需超过
  `EARLY_STOP_MIN_DELTA = 1e-4`）就提前结束。

| 只留全局 token（去掉逐残基结构） | 3.0525 | **+28.80%** |

打乱条件让损失上升 19.0%，说明模型并非只记住了肽的先验分布；再去掉逐残基结构、
只留全局 ESM 均值，损失再升 28.8%，说明 3D 结构分支提供了全局序列表征之外的信息。

第一行的 2.3699 与训练日志里记录的验证损失 2.3700 一致——诊断脚本复用的正是训练时的
验证协议（同一组 `VAL_T_STEPS`、同一套掩码随机流），因此这三行可以直接和训练曲线对照。

界面预测（辅助任务，252,641 个验证残基，界面占比 12.1%）：
**AUROC 0.895 / AUPRC 0.621**（平凡基线 BCE 0.3680）。
按常见判据 AUROC > 0.85 算可用；但距离"直接拿预测口袋做两阶段生成"所需的约 0.93
还有差距，所以没有走"先预测口袋、再按口袋生成"的路线。

### 5.2 过拟合与参数规模：为什么不压参数

同一确定性协议下，训练子集（600 条）1.1443 vs 验证集 2.3699，**差 +1.2257**；
界面 BCE 0.1527 vs 0.2363。9,695 条样本撑不起 7.96 M 参数，过拟合是明显的。

但**压参数并不能解决它**。同协议重训 + 重测了三组配置：

| 配置 | 参数量 | 最优 val | 打乱条件 | 去掉残基 | 生成 KL | 长度 TV |
|---|---|---|---|---|---|---|
| **FFN 2048 / 长度头 256（采用）** | 7.96 M | **2.3700 @ e25** | **+18.99%** | +28.80% | **0.0074** | 0.1246 |
| FFN 1024 | 5.86 M | 2.4144 @ e16 | +12.4% | +15.2% | 0.0094 | 0.1283 |
| FFN 1024 + WD 1e-4 + 坐标抖动 + 长度头 64 | 5.54 M | 2.4110 @ e16 | +12.5% | +18.3% | 0.0124 | 0.1084 |

> 两个瘦身配置的两列诊断值来自同一脚本的早期运行（掩码随机流的实现与 `analyze_run.py`
> 现版本略有出入，绝对值差约 3%），因此只作行内相对比较。三个配置的 val、KL、长度 TV
> 都可由训练日志与 `evaluate.py` 完整复现。

1. 两组瘦身模型的 val 都约 2.41、都在 epoch 16 达峰——这是 FFN-1024 模型的属性，与额外正则无关。
2. "过拟合差距收窄"是假象：它几乎全靠训练损失上升，验证损失反而更差（2.3700 → 2.4144 / 2.4110）。
   加正则只是让模型更难拟合，并没有学到更可泛化的东西。
3. 条件利用能力的下降只来自 FFN 削减（8×d_model → 4×d_model）：打乱条件后损失只上升 12.4%，
   相当于把"用上蛋白条件"的能力削掉三分之一，而这个项目的核心能力正是条件生成。
   长度头压到 64 还会开始输出越界长度（0/35/41/49）。

因此保留 FFN 2048 / 长度头 256。瓶颈不在参数规模：训练全程恒定 `lr=1e-4`、
没有 warmup 与学习率衰减，这更可能是验证损失停在 2.37 的原因。

### 5.3 外部结构验证：用 AF3 检验生成肽能否形成稳定界面

前面的指标衡量的是"像不像真实肽"，回答不了"能不能结合"。为此补了一组
**完全独立、与训练无关**的验证：用 AlphaFold 3 预测 蛋白–肽 复合物结构，读取界面
置信度 **ipTM**（0–1，越高表示模型越确信两者形成稳定界面）。天然配体作为阳性对照。

AF3 是一个真正独立的评判者：它的训练数据、损失函数与本文模型毫无交集，
也没有见过任何一条生成序列——它给出的分数不构成循环论证。

**选靶规则先定后跑**：在 683 个留出蛋白中按界面残基数量与蛋白长度筛出候选，覆盖界面残基
6–79 的整个范围；靶点在运行 AF3 之前确定，之后没有根据分数更换或增删，
**全部 20 个结果照原样报告**。同一规则下的候选清单由 `export_val_proteins.py` 产出
（`val_proteins.csv` 含 `n_iface` / `protein_len` / `true_peptides` 等列）。
每个靶点 5 条生成肽 + 1 条天然配体作为阳性对照。

| 靶点 | 界面残基 | 天然配体 ipTM | 生成肽 ipTM（均值 / 最好） | 天然 − 最好生成 |
|---|---|---|---|---|
| 6BVV-B-A | 79 | 0.84 | 0.59 / 0.76 | +0.08 |
| 8D5N-B-A | 50 | 0.95 | 0.74 / 0.93 | +0.02 |
| 7SL5-I-G | 20 | 0.55 | 0.53 / 0.64 | −0.09 |
| 1U8H-C-A | 6 | 0.66 | 0.74 / 0.82 | −0.16 |

**结论一：在界面明确的靶点上，排序与天然配体一致。**
6BVV（79 个界面残基）天然配体 0.84，5 条生成肽最好 0.76，全部低于天然配体；
8D5N（50 个）天然配体 0.95，最好一条 0.93，达到天然配体的 **98%**。
这两个靶点的蛋白在训练中完全未见过，分数由一个与训练过程毫无关系的外部模型给出，
是最干净的一条证据：生成肽被预测为与靶点形成稳定界面，强度接近天然配体。

**结论二：ipTM 的判别力随界面变小而衰减，这恰好划出方法的适用边界。**
上表最后一列从 +0.08 单调走到 −0.16。1U8H 只有 6 个界面残基、基本没有口袋，
一条 11-mer 生成肽却拿到 0.82，高于 7-mer 天然配体的 0.66——这不是模型变强，
而是 AF3 在小界面上"任何短肽都能被摆进去"，分数饱和。因此本方法的结构验证应当
**限定在界面残基 ≥50 的靶点上**；相应地，6BVV / 8D5N 的结论正好落在工具最可靠的区间，
可信度更高。另：pTM 在同一靶点内波动 ≤0.03（主要由蛋白链折叠决定），不用于区分肽。

**结论三：生成结果是"可被结构模型接受的界面肽"，而非随机序列。**
20 条生成肽长度 5–12、组成均为疏水/极性混合，全部被 AF3 给出界面置信度
（ipTM 0.38–0.93，中位数 0.66），没有出现无法折叠或明显不合理的输出；
pTM 与天然配体处于同一区间（0.66–0.91 vs 0.67–0.90）。这说明生成分布确实落在真实
界面肽的流形附近——与 5 节的 KL 0.0074、非法长度 0 相互印证，而这一次是由结构模型、
而不是序列统计给出的。

**局限与下一步**（四条均已定位到具体动作）：

1. **缺诱饵臂。** 上述都是绝对值，没有下界。下一步为每个靶点造 3 条长度与氨基酸组成
   匹配的诱饵肽（打乱残基顺序，组成不变），共 12 个作业，才能把"生成肽显著优于诱饵"
   从一个描述变成可检验的断言。
2. **小界面靶点上 ipTM 失效。** 后续在这些靶点改用界面 PAE、界面接触对数、
   埋藏面积（buried SASA）等更细的指标。
3. **样本量。** 4 个靶点是案例研究而非统计结论；全量 683 个靶点的统计拟用独立的
   PPI 判别器（PepLM-GNN，5 折集成）批量打分替代。
4. **序列层面的两个已知改进点。** ①4.13% 的完全匹配集中在训练集中出现频次极高的
   短肽上——少数肽在数十个复合物中重复出现，模型在条件信息不足时会调出它们，
   可用高频肽降采样缓解。②跨靶点存在共享局部骨架的倾向（如 `SG-x-QE-A-K`），
   说明条件强度是连续谱而非全有全无；对应改进是在训练目标中加入跨蛋白对比项，
   并把"同蛋白内 Diversity"扩展为跨蛋白多样性指标。

# 基于条件离散扩散模型的蛋白质结合肽生成

给定一条蛋白质的序列，用掩码式离散扩散模型（masked diffusion）生成可能与它结合的多肽。
课程设计项目，代码可复现。技术栈：PyTorch、Transformer、离散扩散。

---

## 1. 任务与数据

**任务**：输入蛋白质序列的表征向量，生成结合肽序列（长度 2~50），即建模 `p(肽 | 蛋白)`。

**数据**：[`Train_Sequences.fasta`](Train_Sequences.fasta)，来自公开的肽–蛋白相互作用数据集（Train_8622）。
记录均来源于PDB中已验证的蛋白质-肽复合物

| 项目    | 内容                       |
|-------|--------------------------|
| 记录数   | 8622 条正样本（`positive_*`）  |
| 覆盖蛋白  | 5688 条唯一蛋白               |
| 正样本长度 | 2~50，均值 18.66，中位数 14     |
| 特殊字符  | 893 条肽含未知氨基酸 `X`         |
| 数据划分  | 按样本随机划分：7759 训练 / 863 验证 |

**蛋白表征**：[`protein_esm.pkl`](protein_esm.pkl)，每条蛋白一个 1280 维向量
（ESM2-650M 提取，预先算好，训练时直接加载）。

## 2. 方法

```text
蛋白序列 ──ESM2-650M──▶ 1280 维条件向量 ──┬─▶ 长度预测器 ──▶ p(k|蛋白) ──采样──▶ k
                                          └─▶ 去噪网络 ◀── 采样窗口 0..k-1 ──┘
                                                 T=100 步去噪 ──▶ 肽序列
```

### 2.1 掩码扩散过程

**前向加噪**：时间步 `t ∈ {0, ..., T-1}`，掩码率 `p_t = t/(T-1)`，
序列的每个位置以概率 `p_t` 被替换为 `<MASK>`；`<PAD>`、`<X>`、`<EOS>` 三类不参与加噪。
`<EOS>` 也排除的理由：它的位置由长度分支预先给定，采样时概率被置 0、不参与去噪；
若允许遮蔽，模型还能从未遮蔽的 `<EOS>` 直接读出长度，造成信息泄漏。

**反向去噪**：从全掩码出发，每一步只对被遮蔽的位置重新采样。对吸收态扩散，
反掩码概率有闭式解 `1 - p_{t-1} / p_t`，不需要额外学一个转移网络。实现见 `diffusion.p_sample_loop`。

**训练损失**（`train.masked_loss`）：把加噪后的 `x_t` 送进网络预测每个位置的原始 token，
交叉熵**只对被加噪的位置计算**，另外补上 `<EOS>` 位置：

- **未加噪的位置不计损失**。模型看得见它们（实测准确率 100%、loss 仅 0.003），
  算进去只是把分母稀释掉；而且采样时只用被遮蔽位置的预测，未遮蔽位的输出根本用不到。
  实测 t=50 时未加噪位占有效位的 51%，旧口径会把损失拉低约 0.02。
- **`<EOS>` 位置计入**。它永不加噪，但必须学会"到此结束"；若不补这一项，
  `<EOS>` 在本设计下会完全失去监督。
- **`<PAD>` 与 `<X>` 天然被排除**：既不加噪、目标也不合法。

### 2.2 去噪网络（`model.ConditionalDecoder`）

| 组件   | 说明                                                                  |
|------|---------------------------------------------------------------------|
| 输入   | `x_t`（B×51）、时间步 `t`、蛋白条件 `cond`（B×1280）                             |
| 词嵌入  | 24 个 token 的嵌入表（20 氨基酸 + `<EOS>` + `<PAD>` + `<MASK>` + `<X>`）      |
| 位置嵌入 | 可学习，51 个位置                                                          |
| 时间嵌入 | 正弦嵌入 + MLP，广播加到每个位置                                                 |
| 主干   | 4 层 `nn.TransformerDecoder`（d_model=256，8 头，dropout 0.1），**双向**自注意力 |
| 条件注入 | 蛋白向量投影到 d_model 后作为交叉注意力的 memory（**单个 token**）                      |
| 输出   | 21 类打分（20 种氨基酸 + `<EOS>`）                                           |

去噪任务是双向的：每个位置都要能看到整条序列，因此不加因果掩码；
肽尾部的 `<PAD>` 通过 `tgt_key_padding_mask` 从注意力中屏蔽。

**条件注入用的是标准交叉注意力**：`cond_proj` 把 1280 维蛋白向量投到 256 维，作为一个
memory token 交给 `TransformerDecoder` 的交叉注意力（Q 来自肽、K/V 来自这个向量）。
肽的 51 个位置各自算一次注意力权重，输出仍是 256 维。

### 2.3 长度预测分支（`model.LengthPredictor`）

肽长不固定（2~50），因此单独用一个分支预测长度：

- **结构**：MLP `1280 → 256 → 256 → 51`，输出 `k = 0..50` 的长度分布，交叉熵训练
- **独立训练**：与去噪网络各用一个 AdamW 优化器，每个 batch 先更新长度分支再更新去噪分支
- **生成时采样长度**：从预测分布里**采样** `k`（而不是取 argmax）。采样保留了分布形状，
  同一蛋白的多条候选肽长度也自然不同；argmax 会一直偏向众数
- **长度不作为网络输入**：`k` 只用于构造采样窗口（`0..k-1` 待采样、第 `k` 位放 `<EOS>`、其余 `<PAD>`）

### 2.4 词表与特殊 token

| 索引   | token    | 作用               |
|------|----------|------------------|
| 0~19 | 20 种氨基酸  | 生成目标             |
| 20   | `<EOS>`  | 肽结束              |
| 21   | `<PAD>`  | 补齐到 51 位，不计损失    |
| 22   | `<MASK>` | 扩散过程的掩码态         |
| 23   | `<X>`    | 未知氨基酸，保留在输入但不计损失 |

## 3. 代码结构

```
config.py       全部超参数（扩散步数、模型尺寸、训练配置、验证协议、早停、词表索引）
data_utils.py   FASTA 解析、编码/解码、Dataset、数据划分
diffusion.py    加噪 q_sample、反向采样 p_sample_loop
model.py        TimeEmbedding / ConditionalDecoder / LengthPredictor
train.py        训练主循环（长度分支与去噪分支独立更新，含早停与最优权重保存）
evaluate.py     批量生成与指标（KL / 多样性 / 完全匹配率 / 长度分布）
generate.py     单条生成示例
```

### 3.1 训练产物与早停

训练时每个 epoch 只写一个 `checkpoints/model_last.pt`（滚动覆盖，不再累积 100 份中间权重），
并在验证损失刷新最优时另存一份 `checkpoints/model_best.pt`：

- **验证损失是确定性的**：固定在一组时间步 `VAL_T_STEPS = (25, 50, 75, 99)` 上算，
  掩码随机场由独立生成器（种子 = `SEED`）给出。这样同一个权重算出的损失与训练跑到第几轮、
  是否触发早停都无关，不同 run 之间可以横向比较。旧的写法每轮重新随机采 `t` 和掩码位置，
  同一权重重测的极差约 0.008，用它做早停判断不可靠。
- **口径与训练一致**：验证损失同样只统计"被加噪位 + `<EOS>` 位"，且**每个时间步等权平均**
  （不是把所有时间步混在一起），因此各时间步的 loss 可以横向比较。
- **不含 `t=0`**：掩码率为 0 时没有加噪位置，只对加噪位置定义的损失无法计算。
- **数值不可与旧版本直接比较**：口径改过（旧版统计全部有效位），因此早停后必须重跑第 5 节指标。
- **早停**：连续 `EARLY_STOP_PATIENCE = 10` 轮验证损失没有改善（改善幅度需超过
  `EARLY_STOP_MIN_DELTA = 1e-4`）就提前结束。
- **`model_best.pt` 里额外存了 `epoch` / `val_loss` / `val_t_steps` / `seed`**，方便回溯是哪一轮、用什么协议选出来的。
- 推理时用 `--checkpoint checkpoints/model_best.pt`；`model_last.pt` 只作诊断用。
- **旧权重 `checkpoints/model_epoch_100_slots_legacy.pt` 已与新结构不兼容**：它含有槽位偏移
  `mem_pos_emb.weight`，而新结构没有这个参数，加载时会报 `Unexpected key(s)`。
  该文件保留仅作历史参考，**推理和评估都必须先重新训练**。

## 4. 环境与运行

```bash
pip install -r requirements.txt

python train.py                       # 训练，早停/最优权重存到 checkpoints/
python generate.py --checkpoint checkpoints/model_best.pt      # 生成示例
python evaluate.py --split val --checkpoint checkpoints/model_best.pt   # 在训练时未见过的蛋白上评估
```

超参数都在 `config.py`：`T_STEPS=100`、`D_MODEL=256`、`NUM_LAYERS=4`、`NHEAD=8`、
`BATCH_SIZE=64`、`LEARNING_RATE=1e-4`、`WEIGHT_DECAY=1e-5`、`EPOCHS=100`、`SEED=42`、
早停与验证协议见 `EARLY_STOP_PATIENCE` / `EARLY_STOP_MIN_DELTA` / `VAL_T_STEPS`。
`DEVICE` 会自动判断 GPU / CPU。

## 5. 结果

在**训练时未见过的 454 条蛋白**上评估，每条生成 5 条肽（共 2270 条），
长度由预测分布采样。

> ⚠️ **下表是槽位机制版本（`MEMORY_LENGTH=16`）的旧结果，已随本次结构改动作废。**
> 改为标准单向量交叉注意力后网络结构变化，**必须重新训练并重跑评估**才能得到可比数字。
> 保留此表仅用于对照参考，复现命令见下方。

| 指标                  | 数值（旧结构，待重测）   | 说明                            |
|---------------------|---------------|-------------------------------|
| KL(P_train ‖ P_gen) | 0.0043        | 生成肽与训练肽的氨基酸组成分布距离，越小越好        |
| Diversity           | 19.44         | 同一蛋白下多条候选肽的平均两两编辑距离           |
| 完全匹配率               | 3.70%         | 与训练集的肽完全相同的比例，即新颖性 **96.30%** |
| 生成长度（均值 / 中位数）      | 20.03 / 15.5  | 真实肽为 18.71 / 14.0             |
| 长度分布 TV 距离          | 0.0967        | 生成长度分布与真实长度分布的全变差距离           |
| 同一蛋白的长度极差           | 17.52         | 采样长度带来的候选多样性（取 argmax 时该值为 0） |

重测命令：`python train.py` 训练完成后 `python evaluate.py --split val --checkpoint checkpoints/model_best.pt`
